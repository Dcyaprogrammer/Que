# 单关核心循环原型规格

状态：用户已授权开始实现；单关原型已实现，规则与界面自动检查通过，等待玩家试玩。
文中“已确认”是访谈决定，“试验方案”与“收尾默认方案”是允许在试玩中调整的实施选择。

## 验证问题

玩家是否会因当前手牌、构筑与剩余资源不同，在“现在结算”与“继续做牌”之间产生有趣的取舍？

Lua / LÖVE 实现一个独立、可反复试玩的单关原型，放在本目录中。
原型用于验证规则，后续正式实现可重写。

## 已确认：手牌与关卡循环

1. 开局选择预设构筑与固定种子，正常洗牌，发出 14 张手牌。
2. 玩家可以换牌，或者提交整手 14 张结算。未胡牌也能结算。
3. 一次换牌随机摸入一张，再弃一张；可以弃掉刚摸入的牌。
   临时持有 15 张期间必须先弃牌，恢复 14 张后才能继续换牌或结算。
4. 每次结算消耗一次结算机会，将本次得分加入关卡累计分数。
5. 结算后整手进入弃牌区；若关卡继续，从剩余牌山重新发 14 张。
6. 整关共享换牌次数与结算次数两份独立资源；结算后均不补充。

初始牌库为万、筒、索各 1–9 加东南西北白发中，共 34 种，每种四张，共 136 张。
整关共用同一座牌山，弃牌不回洗，也不会再次抽到。

## 已确认：计分与胡牌

- 全部 14 张各计一次单牌分值，孤张也有基础收益；牌面数字不直接决定分值。
- 对子、顺子、刻子提供额外组合奖励；每张牌最多属于一个局部组合。
- 系统自动选最终得分最高的拆法，包含强化、道具和胡牌收益的影响。
- 只支持四面子加一雀头的胡牌结构，不支持七对子与国士无双。
- 结构完整且至少有一个受支持的役，才能获得胡牌奖励。
  完整但无役的手牌仍可普通结算，获得单牌分值与局部组合奖励。

第一版的役按以下条件定义：

| 役 | 条件 |
| --- | --- |
| 断幺九 | 全手只有 2–8 的数牌 |
| 三元牌刻子 | 白、发、中每组成一组刻子，各算一项役 |
| 对对和 | 四组刻子加一对雀头 |
| 清一色 | 全手只有同一种花色的数牌，不含字牌 |

暂不实现门前清自摸等其他役，也不照搬日麻的番符与点数结算。

## 已授权调参：计分与构筑试验方案

用户将分值、倍率、构筑效果强度等计分设计委托给实现者选择；这些是后续优化项，
不要求在编码前固定。实现时提供集中、可调整的默认参数。

起始试验公式：

```text
本次得分 =（14 张单牌分值之和 + 所选拆法的组合奖励 + 道具加分）× 胡牌倍率
```

普通结算倍率为 1；有役胡牌的起始试验倍率为 1 加成立的役项数。
三元牌刻子逐组计项，其他每种役最多计一次。倍率方案与各项数值均允许随试玩调整。
役只在完整胡牌拆法上成立，未成牌时满足花色等表面条件不会提前获得役倍率。

三套起始预设：

| 构筑 | 起始试验效果 |
| --- | --- |
| 重五 | 三种花色的所有五提高单牌分值 |
| 顺子 | 提高顺子的组合奖励 |
| 刻子 | 所选刻子内的牌额外计单牌分值，包含已有强化收益；重复次数为可调参数，首轮设为两次 |

三套均不增减牌，也不改变洗牌顺序；同种子使用同一副发牌顺序和相同关卡资源。
基础分、组合奖励、强化幅度、胡牌倍率及目标分数由实现者给可调默认值。

## 已确认：信息与复现

- 实时预览当前手牌立即结算的准确得分，并展示单牌、组合、道具、胡牌的贡献。
- 显示牌山剩余张数及本关全部弃牌，包含换牌弃牌与结算弃掉的整手牌。
- 隐藏牌山顺序。
- 使用一组固定种子正常洗牌发牌，支持同种子重玩，以比较不同构筑。

## 收尾默认方案：边界与操作

- 每次摸牌时扣一次换牌次数；弃牌不另收费。等待弃牌时禁止再次摸牌与结算。
- 换牌次数为零或牌山为空时禁用摸牌，仍允许对当前完整手牌结算。
- 结算后先判断累计分数是否达标：达标即胜利。
  未达标且结算次数耗尽则失败；否则发下一手。
- 若关卡仍需继续但牌山不足 14 张，则失败并说明原因，不发残缺手牌。
- 初始资源数量由实现者给可调默认值；正常默认配置满足
  `14 × 可结算次数 + 可换牌次数 ≤ 136`，避免正常测试被牌山不足打断。
- 每份候选拆法独立判断是否完整、有役并计算最终分，不能用另一份拆法的役或奖励。
  得分相同的拆法使用稳定次序选择，预览与实际结算保持一致。
- 鼠标点击按钮摸牌、点击手牌弃牌、点击结算按钮提交；显示当前操作提示与选中牌反馈。
- 开局选择构筑和种子；结果界面支持同配置重试、换种子或返回构筑选择。
  重试重置整关的牌、强化与资源，不继承上一轮状态。
- 使用清楚可辨的简单牌面与文字，突出所选计分组合，先做必要交互反馈。
  第一版不实现鸣牌、杠、对手、商店、多关流程、存档或正式美术音效。

## 验证与试玩收尾默认方案

交付试玩前检查：

- 可用 `love` 命令启动，运行检查与截图无报错。
- 发牌、摸切、结算、胜利、失败、重开均能完成，资源不会变负，牌不会重复或丢失。
- 覆盖普通手牌、完整无役手牌、四类役、多种拆法、构筑效果和牌山不足的计分与状态检查。
- 预览与结算相同，同种子同操作可复现；正常开局由洗牌生成。
  人工构造的成牌案例只用于检查规则，不伪装成正常随机开局。

试玩时记录使用的种子、构筑、参数、结算得分与剩余资源，并重点观察：

- 玩家是否能从得分拆解说明保留或弃掉某张牌的理由。
- 是否出现随手牌与资源变化而改变结算时机的选择。
- 相同种子使用不同构筑，是否改变留牌与配型策略。
- 胡牌是否有实际追求机会，玩家是否愿意主动再玩一局。

如果始终立刻结算或始终等胡牌，先调整资源与收益；不能仅因一组参数表现差就否定整个方向。
第一轮聚焦尽快打通可试玩的完整循环，不追求发布品质。
