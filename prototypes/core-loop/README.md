# Que · 单关原型

在项目根目录运行：

```sh
love prototypes/core-loop
```

也可从任意目录运行：

```sh
love /Users/dopamine/Que/prototypes/core-loop
```

直接进入第一人称牌桌试玩：

```sh
love /Users/dopamine/Que/prototypes/core-loop --play
```

需要 LÖVE 11.5。无第三方 Lua 依赖；当前 macOS 原型读取系统中文字体，不复制或分发系统字体。
其他平台需在 `main.lua` 的字体路径列表中提供可用的中文字体，发布前应捆绑许可合适的字体。

## 怎样玩

1. 选择重五、顺子或刻子构筑，再选择固定种子开始。
2. 点击绿色牌山或按空格，随机摸一张；点击任意手牌打出，也可以弃掉新摸的牌。
3. 摸牌后，将鼠标移到手牌上，可查看弃掉它之后的精确得分。
4. 按下桌沿红色结算按钮或按回车，将整手牌计分并弃置。未胡牌也有分数。
5. 本关目标为 850 分，48 次换牌和 3 次结算在整关共享。牌山不回洗。
6. 结果界面可同配置重试（R）、换下一个种子，或返回构筑选择（Esc）。

也可以按住手牌拖到桌心打出；在其他位置松开则回到手中，不消耗额外资源。
手牌下沿的颜色对应计分组合。点击左侧记分单查看完整分数拆解；点击弃牌记录翻看全部弃牌，并用滚轮翻页。
桌心展示最近 24 张弃牌。M 切换声音，V 切换减少动效（关闭视差和自动飞牌），也可点桌沿开关。
Esc 会先取消拖拽或合上记分单/记录本，再按则返回构筑选择。
返回构筑选择后重新开始会重置本关，当前不提供存档。

牌桌采用固定第一人称透视，牌面、木纹、台呢与短音效由代码生成，没有新增第三方依赖或外部美术音频。
设计构图与交互思路见 [PLAYGROUND.md](PLAYGROUND.md)。

## 调参

所有起始分值、构筑强度、资源次数、目标分数和种子集中在 `config.lua`，修改后重启生效。
初始单牌 10 分；对子 +12、顺子 +32、刻子 +36。普通结算倍率为 1，有役胡牌倍率为 `1 + 役项数`。
重五让所有五的单牌分值 +20；顺子构筑每组顺子再 +32；刻子构筑额外计两次刻子成员的单牌分值。

完整规则见 [BRIEF.md](BRIEF.md)，领域术语见项目根目录 `CONTEXT.md`。
`rules.lua` 计算最高分拆法；`run.lua` 管理牌山、手牌、弃牌及资源；`main.lua` 连接界面与输入。
`tabletop.lua` 绘制透视牌桌并处理拖拽，`table_art.lua` 创建静态贴图，`table_feedback.lua` 管理动效与短音效。

## 验证

从项目根目录运行：

```sh
love prototypes/core-loop --test
love prototypes/core-loop --test --benchmark
love prototypes/core-loop --smoke --frames 150 --shot table-playground.png
```

`--test` 不创建窗口。覆盖四类役、完整无役手牌、普通手牌、七对子/国士不受支持、
最优且不重叠的拆法、单张强化的重复收益、同种子复现、非法操作、资源耗尽、牌山不足及最后机会达标。
还运行 10,000 次随机合法操作检查 136 张牌的身份守恒，并运行 24,000 次四张牌洗牌检查分布。
当前检查全部通过；洗牌 24 种排列全部出现，卡方统计量 16.89（检查阈值 41）。
另覆盖透视大小、四边形命中、动画被打断后从当前位置续接、动画结束及减少动效。

`--smoke` 自动点击真实 LÖVE 输入回调，覆盖三种构筑、种子选择、摸切、悬停预览、结算、
失败/胜利、重试、换种子、缩放、全部弃牌滚动及胡牌计分显示；检查图像输出，并以正常目标与正常随机开局结束。
胜利界面检查临时使用目标 1，属于显式测试情形，不是正常关卡或真实通关率的证据。
该检查也覆盖第二手等待弃牌时不能显示上一手得分，以及重开时清除上一局结算提示的问题。
第一人称界面检查还覆盖拖拽打牌、无效拖拽取消、计分单与弃牌记录展开、静音与减少动效。
缩放后会读取实际画面中的牌面像素，防止只通过输入检查却没有正确绘制牌面。
已确认使用 Canvas 缓存会在窗口模式切换后丢失内容；静态贴图改存 Image，保留了实际复现的失败/通过检查。

截图与日志位于 LÖVE 存储目录；macOS 为：

```text
~/Library/Application Support/LOVE/que-core-loop/
```

正常游玩日志为 `playtests.tsv`，自动界面检查使用独立的 `smoke.tsv`。
日志包含时间、种子、构筑、动作、牌实例 ID、结算分数、累计分数、剩余资源、役及所用参数；不会上传。

## 初始校准记录

2026-11-12：每套构筑在相同的 21 个正常随机种子（1001–1021）上运行贪心机器人。
机器人每手分配 16 次摸牌，每次只选择当前得分最高的弃牌，再结算；每套共 1008 次摸牌、63 手。

| 构筑 | 平均每手分数 | 达到 850 分的局数 | 有役胡牌手数 | 立刻结算三手的平均总分 |
| --- | ---: | ---: | ---: | ---: |
| 重五 | 299.7 | 17 / 21 | 1 / 63 | 609.7 |
| 顺子 | 294.2 | 11 / 21 | 1 / 63 | 580.8 |
| 刻子 | 291.9 | 9 / 21 | 1 / 63 | 561.0 |

此机器人只看当前分数，不优化向听数或未来摸牌，因此不是最优打法，也不代表玩家通关率。
胡牌偏少是优先观察的问题。正常开局不安排接近胡牌的手牌，也不暗改牌山。
人工成牌手牌只用于规则检查；有趣程度、是否愿意再玩及最终保留/调整决定，仍待玩家试玩。
